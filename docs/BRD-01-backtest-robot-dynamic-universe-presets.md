# BRD-01: Бэктест торгового робота с динамической вселенной и пресетами

**Версия:** 1.0  
**Дата:** 2026-05-12  
**Статус:** Утверждёно к передаче системному аналитику  
**Идентификатор для трассировки:** `[ref: BRD-01]`

---

## 1. Executive summary

- **Цель:** воспроизводимая оценка робота на исторических данных с тем же бизнес-контуром, что и в проде: периодическое формирование списка торгуемых бумаг, расчёт индикаторов, правила входа/выхода, учёт издержек и лимитов портфеля.
- **Вселенная:** ликвидные акции MOEX с настраиваемыми порогами (оборот, цена, топ-K, секторные/именные ограничения, blacklist/whitelist).
- **Edge (гипотеза):** качество результатов определяется совместным выбором universe, параметров сигнала и профиля риска; три пресета (агрессивный, рациональный, стабильный) фиксируют типичные компромиссы без ручной настройки десятков полей в каждом прогоне.

---

## 2. Market context (MOEX)

- Режимы рынка РФ (ключевая ставка, курс RUB, санкционные/корпоративные новости) влияют на гэпы и ликвидность; бэктест должен позволять **выделить стресс-периоды** в отчёте (квартальная разбивка).
- Основная сессия MOEX и аукционы: правила исполнения в симуляции должны быть **однозначны** (например, сигнал на закрытии дня → сделка на открытии следующего дня) и не использовать внутридневной high/low без отдельной внутрибаровой модели.
- Примеры тикеров для тестовых сценариев: SBER, LKOH, GMKN, NLMK, ROSN, TATN, MOEX, YDEX (не исчерпывающий список).

## 3. Signal and rules (business level)

### 3.1. Автоопределение списка бумаг (universe selection)

1. **Базовый пул (конфиг):** индекс / сектор / ручной whitelist / blacklist (микрокапы, низкий free-float, спецрежимы листинга — по бизнес-решению).
2. **Фильтры ликвидности:** минимальный дневной оборот в рублях, медиана объёма за N дней; опционально исключение аномальных дней (winsorization).
3. **Фильтры цены и качества ряда:** минимальная цена; политика по пропускам свечей (см. §4.3).
4. **Концентрация:** максимальная доля эмитента/сектора в кандидатном списке до входа в портфель; опционально — упрощённый контроль факторной убыточности (сектор).
5. **Ребалансировка universe:** период T (дни) или на каждом баре; момент применения фильтров относительно сигнала — зафиксирован в симуляции.
6. **Causality:** для решений на дату t показатели ликвидности/ранжирования используют только данные, доступные **не позднее t−1** (или согласованное правило), без look-ahead.

### 3.2. Тонкая настройка параметров

Группы параметров (все численные, с диапазонами и дефолтами):

| Группа | Примеры |
|--------|---------|
| Universe | окно ликвидности, порог ADV/оборота, топ-K, секторные капы, whitelist/blacklist |
| Сигнал | периоды индикаторов, пороги пересечений/z-score, минимальная «сила» тренда |
| Риск | стоп %, трейлинг, тайм-стоп (в барах), макс. позиция % NAV, макс. число позиций |
| Симуляция исполнения | комиссия bps, slippage (фикс. bps или доля спреда), цена исполнения (mid / close / close ± slippage) |
| Капитал | стартовый NAV, лотность, округление |

**Приоритет:** пользовательские оверрайды перекрывают значения пресета для явно заданных полей.

### 3.3. Пресеты

| Пресет | Намерение | Качественный профиль |
|--------|-----------|----------------------|
| **Агрессивный** | выше целевая доходность за счёт риска и оборота | шире universe или мягче ликвидность; выше вовлечённость; более жёсткие acceptance по доходности, мягче по max DD относительно других пресетов |
| **Рациональный** | баланс risk-adjusted доходности и оборота | стандартные ликвидностные пороги; умеренный размер позиции; типичные стопы/тайм-стопы |
| **Стабильный** | ниже волатильность портфеля, меньше оборот | жёстче ликвидность и лимиты концентрации; меньше одновременных позиций; консервативнее сценарии издержек в acceptance |

Пресет = именованный снимок набора параметров по группам + связанные **бизнес-пороги acceptance** (§8).

### 3.4. Вход / выход / удержание

- **Вход:** условия робота (сигнал) + допустимость по universe и лимитам портфеля; порядок при множественных сигналах (например, по силе сигнала или ликвидности) — настраиваемое правило.
- **Выход:** стоп-лосс, трейлинг (в % от входа или в единицах ATR), тейк-профит, тайм-стоп, выход по развороту сигнала (если заложено в стратегии).
- **Удержание и оборот:** ожидаемый горизонт позиции задаётся параметрами тайм-стопа и волатильности; turnover контролируется через размер позиции и частоту сигналов.

## 4. Instruments

- **Класс активов:** преимущественно акции MOEX (RUB PnL).
- **Исключения:** илликвидные имена ниже порога оборота; инструменты с систематически неполными рядами — по политике blacklist или автоматическому исключению на период дыры.

---

## 5. Position sizing and capital

- Максимальная доля NAV на одно имя и на сектор (численно в параметрах).
- Максимальное число открытых позиций.
- Опционально: нормировка размера позиции на ATR / волатильность (vol targeting).
- Ребалансировка: по сигналам и жёстким выходам; без неявного «доливания» вне правил робота.

---

## 6. Data and execution dependencies (T-Investments)

- **Данные для бэктеста:** исторические свечи (OHLCV) через REST (`GetCandles` / эквивалент в продукте); интервалы — минимум дневной для первой версии; часовой — если стратегия робота это требует.
- **Идентификация инструментов:** разрешение тикера → FIGI (или используемый в проекте идентификатор) с версионированием справочника на дату t.
- **Корпоративные действия:** политика BRD — adjusted prices vs денежные потоки по дивидендам; сплиты; делистинг → принудительный выход по последней валидной цене с логированием причины.
- **Латентность:** в бэктесте не моделируется сеть; в live-алайнменте учитывать задержку REST/WebSocket отдельно (вне scope симуляции v1, но зафиксировать в ограничениях).

## 7. Индикаторы и показатели

### 7.1. Для сигнала и отбора (базовый универсальный набор)

- OHLCV на выбранном интервале.
- Тренд: SMA/EMA; при необходимости MACD, ADX или proxy силы тренда.
- Волатильность: ATR или стандартное отклонение доходности — для стопов и размера позиции.
- Моментум: RSI, ROC, breakout от N-дневного high/low — если используется в логике робота.
- Ликвидность: скользящий средний оборот (руб.), относительный объём.

### 7.2. Метрики результата бэктеста

Обязательная таблица метрик (горизонт явно указывается, при периоде &lt; 1 года CAGR помечается как опциональный):

| Метрика | Определение (одна строка) | Примечание |
|---------|---------------------------|------------|
| Доходность за период / CAGR | по equity curve | CAGR только при достаточном горизонте |
| Волатильность (год.) | σ дневных доходностей × √252 | |
| Sharpe (год.) | (R − Rf) / σ; Rf по умолчанию 0 в BRD | |
| Max drawdown | пик–дно по equity | обязательно рядом с доходностью |
| Calmar | CAGR / \|max DD\| | опционально |
| Win rate | прибыльные round-trip / всего сделок | |
| Avg win / avg loss | среднее PnL выигрышных / \|среднее убыточных\| | |
| Exposure | средняя вовлечённость % NAV | |
| Turnover | годовой traded notional / NAV | чувствительность к издержкам |

**Издержки:** комиссия (bps), slippage; обязательные сценарии чувствительности: **costs +50%**, **slippage ×2**.

**Бенчмарк:** IMOEX или пассивная стратегия «тот же universe, без сигнала робота» — для разделения alpha и рыночного beta.

## 8. Backtest requirements (симуляция и acceptance)

### 8.1. Scope

- Стратегия: торговый робот с динамической вселенной и пресетами параметров `[ref: BRD-01]`.
- Диапазон дат и опционально train / validation / hold-out — задаются при запуске.
- Версия правил робота и версия пресета — обязательные поля результата.

### 8.2. Имитация сигналов и исполнения

- Сигнал на баре **t** исполняется по **одной** выбранной модели на весь прогон (например: t+1 open, t close, t+1 close). Запрещено покупать «по low» бара t без внутрибаровой модели.
- Сначала определяется допустимый universe на дату (без look-ahead), затем считаются индикаторы и применяются правила входа.
- Пропуск данных: явная политика (нет сигнала / перенос / исключение инструмента на период).
- Лотность: целые лоты или дробление по настройке; опциональный cap на долю ADV для крупного NAV.

### 8.3. Выходные артефакты бэктеста

**Графики:**

1. Equity (руб. и/или %) + бенчмарк.
2. Underwater / drawdown от пика.
3. Помесячная доходность (heatmap или столбцы).
4. Распределение дневных доходностей стратегии.
5. Exposure / gross exposure во времени.
6. Turnover по времени или по месяцам.

**Таблицы:**

- Сводка метрик по каждому пресету и по сценариям издержек.
- Журнал сделок: дата входа/выхода, тикер, сторона, qty, цены, PnL, длительность, причина выхода.
- Вклад по инструментам (топ виннеры/лузеры).
- Вклад по кварталам.

**Дополнительно для динамической вселенной:** эволюция состава universe/портфеля по секторам (stacked area или аналог).

### 8.4. Acceptance criteria (бизнес)

- Пороги **Sharpe / max DD / alpha к бенчмарку** задаются отдельно для каждого пресета (агрессивный допускает большую просадку при более высокой целевой доходности; стабильный — наоборот).
- Стратегия «стабильный» не должна при **удвоенных** совокупных издержках переходить в устойчиво отрицательное мат. ожидание (порог задаётся численно на этапе согласования).
- Отчёт обязан содержать сценарии чувствительности из §7.2.

### 8.5. Ограничения модели (out of scope v1)

- Не моделируются: очередь лимитов, глубина стакана, частичные исполнения по очереди, market impact для очень крупного размера.
- Микроструктура внутри бара не моделируется без отдельного BRD.

## 9. Risk assessment

| # | Зона | Серьёзность | Суть | Митигация |
|---|------|-------------|------|-----------|
| 1 | Ликвидность | M–H | второй эшелон в universe | жёсткие пороги ADV, топ-K, сценарии slippage |
| 2 | Look-ahead / survival | M | смещение при отборе | правила на t−1, делистинги, качество справочника |
| 3 | Данные API | M | пропуски свечей, лимиты | кэш, MSK/UTC, контроль качества рядов |
| 4 | Стадия рынка РФ | M | корреляции под стрессом | секторные капы, квартальные отчёты |
| 5 | Операционка | L | токен/брокер | вне бэктеста; для live — отдельный runbook |

**Остаточный риск:** симуляция завышает реализуемость для агрессивного пресета относительно live-исполнения при тех же правилах.
